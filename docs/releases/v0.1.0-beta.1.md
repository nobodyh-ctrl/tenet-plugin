# tenet 0.1.0-beta.1

**First public beta.** tenet is ready to try in real projects, but it is still beta. Commands, rule texts and guard policy may change before 1.0, and some paths have only been tested on Windows. Your feedback decides what 1.0 looks like.

## What's in this version

### Workflows you can ask for in plain language
- **Engineering:**
  - `feature`: plan, build, verify, review and document.
  - `bugfix`: reproduce, root cause, minimal fix, regression test.
  - `release`: prepare everything, then stop for your approval.
  - `project-init`: onboard a new or existing repository without imposing a stack.
- **Building blocks:** `plan-work`, `implement`, `review-code`, `verify-changes`, `documentation`, `devops-iac`.
- **Learning:** `study-topic`, `learn-concept`, `hands-on-lab`, `research-technology`, `aws-security`, `networking-lab`. Lessons are staged and include comprehension checkpoints you can skip.
- **`/tenet:version`:** shows the installed version and channel. New in this release.

### Agents
- `explorer`, `architect`, `implementer`, `reviewer`, `security-reviewer`, `tutor`.
- Each gets the minimum tools it needs.
- Reviewers are held to read-only by the guard hook, not just by instructions.

### Safety
- The guard hook:
  - blocks clearly destructive commands (deleting root or home, formatting disks, force-pushing `main`);
  - asks before risky ones (push, releases, `terraform apply`, `kubectl delete`, global installs, `sudo`, `curl | sh`);
  - protects secret files.
- It works even when an allow rule would permit the command.
- Optional second-layer `ask`/`deny` permission rules.

### Method and memory
- Short always-on rules (~60 lines): source of truth, spec-driven development with OpenSpec, task sizing, delegation, token efficiency, autonomy limits.
- Engram persistent memory: targeted recall, saved decisions and lessons, session summaries. Memory never overrides code or specs.
- A private profile per person (language, experience, learning goals) that never leaves your machine.

### Engineering Manual
- Standards marked `MUST`, `SHOULD` or `EXPERIMENTAL`, covering core engineering, delivery and IaC, security, and AWS as the first provider.
- Technology and tool catalogs, with evidence for each assessment.
- Loaded only when a skill needs it.

### Installer
- Windows PowerShell and Linux/Git Bash.
- Dry-run, backups with byte-identical restore, an ownership manifest, idempotent re-runs, and an uninstall that removes only what tenet added.

## Install

```bash
claude plugin marketplace add nobodyh-ctrl/tenet-plugin
claude plugin install tenet@tenet
```

For the rules, profile and Engram wiring, clone the repo and run `installers/install.sh --with-plugin --with-engram`, or `.\installers\install.ps1 -WithPlugin -WithEngram` on Windows. Preview first with `--dry-run` (`-DryRun`). See [installation.md](../installation.md).

Check the version inside Claude Code with `/tenet:version`, or in a terminal with `claude plugin list`.

## Try it

1. Restart Claude Code after installing.
2. Ask in plain language: *"Booking returns 500 when the class is full. Fix it."* or *"I want to understand VPC subnets."*
3. Run `/tenet:project-init` in a new repository.

## Known limitations

- **Tested platforms.** Tested on Windows 11 with Claude Code 2.1.296. Linux is covered by CI unit tests only.
- **The guard is not a sandbox.** Deliberately obfuscated commands can evade it. It also fails open when bash or Python 3.9+ is missing; `scripts/doctor.py` reports that case.
- **Possible prompts from subagents.** `architect` and `security-reviewer` may ask permission to read Engineering Manual files in interactive sessions.
- **Skill selection is a judgment.** Claude usually picks the right workflow from your words. Use `/tenet:<workflow>` to force one.
- **Engram is optional.** Without it, memory steps are skipped. Version 3.4+ is recommended.

## Feedback

Open an issue with:
